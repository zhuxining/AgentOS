# Read

阅读分析技能，负责把已有内容或链接内容转化为摘要、要点和结构化理解。

## 触发边界

| 用户意图 | 处理 |
|------|------|
| 读一下、总结、分析、提炼要点、解释这篇文章 | 使用本技能 |
| 用户粘贴长文本、文章、论文、访谈、报告 | 使用本技能 |
| 用户提供 URL 并要求阅读或分析 | 先提取正文，再进入本技能分析流程 |
| 用户只要网页原文 Markdown | 使用 `fetch` |
| 用户要搜索资料或找更多来源 | 使用 `search` |

## 输入处理

- **粘贴正文**：直接分析。
- **URL**：先按 `fetch` 的提取流程取得标题、URL、提取状态和正文，再分析。
- **多个 URL 或多篇正文**：逐篇提取核心信息，再做横向比较。
- **内容过短或提取失败**：说明原因，并给出可继续处理所需的信息。

## URL 降级处理

`read` 消费 `fetch` 的三态结果：

- **成功**：基于完整正文输出摘要、关键要点、适用维度分析和实体提取。
- **部分成功**：基于可用正文做有限分析，明确标注缺失范围；不推断作者、日期、结论或上下文中没有的信息。
- **失败**：如果用户同时提供了正文片段，改用片段分析；否则返回 `fetch` 已尝试路径和失败原因，并请用户提供可访问链接或正文。

## 分析流程

根据内容类型选择性应用分析维度。详细模板见 `references/analysis-template.md`。

| 内容类型 | 适用维度 |
|---------|---------|
| 深度文章、评论、论文 | 文本解构、概念提炼、批判审视、思想深化、实践转化 |
| 新闻、产品页 | 文本解构、概念提炼、实践转化 |
| 教程、技术文档 | 文本解构、概念提炼、实践转化 |
| 数据页、API 文档、参考表 | 跳过五维分析，直接整理结构和关键字段 |

## 输出格式

```markdown
## [标题](url)

**作者**: xxx | **日期**: xxx | **字数**: xxx

### 摘要
一段话总结。

### 关键要点
- 要点一
- 要点二
- 要点三

### 分析
[按适用维度输出]

### 实体
- 工具/软件：
- 公司/组织：
- 人物：
- 书籍/论文/资源：
```

## 委托协议

其他技能可委托 `read` 分析正文或链接。被委托时：

- 返回标题、URL、摘要、关键要点、适用维度分析、实体提取。
- 如果调用方需要完整正文，同时附上提取到的干净 Markdown。
- 不主动追问用户；信息不足时说明缺口和影响。
