# Search

搜索与调研技能，只负责**发现和综合信息来源**。如果用户要读取某个链接全文、提取网页正文或分析文章内容，应改用 `fetch` 或 `read`。

## 触发边界

| 用户意图 | 处理 |
|------|------|
| 搜索、查找、调研、找资料、查最新信息 | 使用本技能 |
| 查询编程库、框架、API、官方文档 | 使用本技能，并优先考虑 `ctx7` |
| 根据一个 URL 搜索更多相似内容 | 使用本技能；必要时把 URL 当作线索，不在本技能内提取全文 |
| 只提供 URL，要提取正文 | 使用 `fetch` |
| 要读链接、总结文章、分析观点 | 使用 `read` |

## 工具选择

| 场景 | 工具 |
|------|------|
| 通用网页搜索 | Agent 自带 `web_search` |
| 候选链接核验或摘要读取 | Agent 自带 `web_fetch` |
| 可复现命令行搜索、需要 JSON 结果或内置搜索不可用 | `scripts/ddgs_search.py` |
| 技术文档查询 | `ctx7` CLI + `web_search` |
| 需要真实网页交互 | `browser-use` |

工具调用细节见 `references/tool-catalog.md`。

## 工作流

### 1. 查询分类

- **技术文档**：涉及编程库、框架、API、SDK、错误信息或配置项时，先用 `ctx7` 定位官方文档，再用 `web_search` 补充。
- **通用查询**：优先使用 Agent 自带 `web_search`；已有候选链接需要核验时使用 `web_fetch`。
- **可复现查询**：需要命令行复现、JSON 输出或内置搜索不可用时，使用 `scripts/ddgs_search.py`。
- **深度研究**：用户明确要求全面、深入、多来源对比，或普通搜索结果不足时，按“发现链”和“核验链”分别降级；只有需要真实页面交互时才使用 `browser-use`。

### 2. 执行搜索

- 独立查询可以并行执行。
- `ctx7` 有顺序依赖：先 `ctx7 library <name> <query>` 解析库 ID，再 `ctx7 docs <libraryId> <query>` 查询文档；每个问题最多尝试 3 次。
- 发现链：`web_search` → `scripts/ddgs_search.py` → `browser-use` 打开搜索页。`web_fetch` 不作为搜索失败后的替代工具。
- 核验链：`web_fetch` 读取候选链接摘要；如果 `web_fetch` 失败、内容不足或需要页面交互，再用 `browser-use`；如果调用方需要完整正文，委托 `fetch`。
- 本地 DDGS 搜索脚本使用 `uv run search/scripts/ddgs_search.py "query"`，需要结构化消费时加 `--output json`；默认使用 `auto` 后端、15 秒超时，并在失败后重试 1 次。
- 对同一主题可以使用不同措辞、语言或 `site:` 限定词提升覆盖度。
- 使用 `browser-use` 时先打开页面，再通过 `state` 找到结果索引，必要时点击进入页面或用 `eval` 提取页面文本。

### 3. 综合结果

1. 按 URL 去重，合并同一来源的重复摘要。
2. 按子主题、可靠性和相关度分组。
3. 优先官方文档、原始出处、权威机构、作者本人或一手数据。
4. 明确标注不确定、过时或来源质量较低的信息。

## 输出格式

```markdown
## 搜索结果：[查询主题]

### [子主题 1]
- 要点摘要（来源：[标题](url)）
- 要点摘要（来源：[标题](url)）

### [子主题 2]
- ...

---
**来源列表**
1. [标题](url) — 简述
2. [标题](url) — 简述
```

## 委托协议

其他技能可委托 `search` 查找资料。被委托时：

- 只返回搜索结论、候选链接和来源质量判断。
- 不主动追问用户。
- 如果调用方需要正文或深度阅读，返回建议委托 `fetch` 或 `read`。
